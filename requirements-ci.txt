# LOCKFILE do ambiente dos FISCAIS — o CI e o `harness/local_validate.sh` instalam daqui.
#
# Por que com hash. Sem `--require-hashes`, um cache envenenado ou um índice trocado entregaria
# outro artefato com o mesmo nome e versão, e o fiscal rodaria em cima dele reportando verde com
# convicção. O hash é o que torna "esta é a mesma dependência" verificável em vez de afirmado.
#
# ESPECÍFICO DE PLATAFORMA, e isso é o custo declarado desta decisão: `--require-hashes` fixa
# ARTEFATOS, e wheel é específico de plataforma. Este arquivo é gerado para o que o CI usa —
# Linux x86_64, CPython 3.11. Em outra plataforma a instalação FALHA explicitamente, e falhar
# explícito é o comportamento certo: a alternativa seria cair para outra resolução em silêncio,
# que é exatamente a divergência que este arquivo existe para impedir.
#
# Distinto de requirements-qa.txt, que declara a RÉGUA (webqa-suite) com pin exato. Aqui é o
# fecho resolvido das ferramentas que rodam os fiscais — não uma declaração de dependência do
# negócio, e por isso não entra em security/dependencies.yaml.
